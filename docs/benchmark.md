## Model comparison (measured)

| Model | Structured JSON quality | Verdict |
|---|---|---|
| `qwen-vl-plus` | Reliable: names, tax ids, amounts, confidence extracted correctly on clean samples | **Default primary** |
| `qwen3.5-ocr` | Poor for structured extraction: `"0"` for party names, all-zero confidence, misread tax-id digits | Fallback only |

`qwen3.5-ocr` is an OCR-layout model; in this chat-completions + JSON schema task it produced unusable structured fields, so `qwen-vl-plus` is the default (`DOCMIND_VISION_MODEL_PRIMARY`).

## Failure analysis

- **Tax ids are the hardest field** (70–72%): 18-character unified social credit codes fail on a single misread digit/letter; the `party_info` rule's GB 32100-2015 check-character validation surfaces most of these as WARNING findings.
- **Totals** (`amount_including_tax` ~80%): occasional decimal/digit errors; `line_items_sum` catches many even when the error is internally consistent at the document level.
- **Failed files** are recorded in `benchmark/results/` with the model error; the extractor retries once and repairs flaky JSON.

## Methodology

- 30 synthetic Chinese e-invoice PDFs (reportlab) with known values;
- 200 dpi PNG → vision model (temperature 0, `json_object`, 1 retry, tolerant JSON parsing);
- exact (normalized) string match for text, ≤ ¥0.02 numeric tolerance for amounts; unverifiable ground-truth fields excluded;
- `benchmark/results/*.json` stores per-run detail; this page is regenerated by `scripts/run_benchmark.py`.
